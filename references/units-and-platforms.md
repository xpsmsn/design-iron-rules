# 单位与平台换算

跨平台交付时最常见的错误是单位混用。此表用于把 L1 定律的数值换算到目标平台。

## 单位对照

| 单位 | 基准 | 何时用 |
|---|---|---|
| `px` | 物理像素（受 DPR 影响） | Web 桌面端、边框、阴影、图标 |
| `rpx` | 750rpx = 屏幕宽度 | 微信小程序、支付宝小程序、Taro、uni-app |
| `rem` | 根元素字号 | 移动 Web 响应式排版 |
| `pt` | 1pt = 1/72 英寸 | iOS 标注、H5 在 iOS 的 CSS 映射 |
| `dp/sp` | 设备无关像素 / 缩放像素 | Android |

### px ↔ rpx 换算

```
rpx = px × (屏幕宽度 / 750)
px  = rpx × (750 / 屏幕宽度)
```

iPhone 6（375pt 逻辑宽）基准：`1px = 2rpx`

常用换算（以 375px 宽为基准）：

| px | rpx | 用途 |
|---|---|---|
| 4 | 8 | 最小间距 |
| 8 | 16 | 图标与文字间距 |
| 12 | 24 | 小间距 |
| 16 | 32 | 标准间距 / 正文基准字号 |
| 20 | 40 | |
| 24 | 48 | 大间距 / 输入框高 |
| 32 | 64 | |
| 40 | 80 | |
| 44 | 88 | **触摸热区下限** |
| 48 | 96 | 移动端输入框高（比 Web 更宽松） |

注意：rpx 会随设备宽度线性缩放。**热区、边框、阴影不要用 rpx**——小屏设备上 2rpx 边框会细到不可见，大屏上阴影会过重。这些用 `px`。

### px ↔ pt

```
iOS 标注 pt × 1.333 = Web px
Web px × 0.75 = iOS 标注 pt
```

### rem 换算

```
1rem = 16px（除非改过 root font-size）
响应式字号用 clamp()：
  font-size: clamp(15px, 2.5vw + 12px, 18px);
```

## 平台差异

### 微信小程序

- 画布固定 750rpx 宽，设计稿标注 750px 宽的稿子
- `rpx` 仅适用于宽度，不适用于高度/字号以外的间距
- 触摸热区建议 ≥ 88rpx（=44px @375 宽）
- 安全区：`safeAreaInsets` / `env(safe-area-inset-bottom)`，底部按钮必须加安全区内边距
- 导航栏高度由系统接管，页面内不要再预留 44px 导航空间
- 下拉刷新、页面滚动由系统提供，不要重复实现
- 组件库风格偏圆润，token 圆角可适当上调（类 Material 2.2）

### H5 / 移动 Web

- 关注 `viewport-fit=cover` 与安全区
- 移动端字号下限 15px（约等于桌面 14px 的观感）
- 300ms 点击延迟：加 `touch-action: manipulation`
- 字号 < 16px 的 input 在 iOS 会触发自动放大，需 `font-size: 16px`

### 桌面 Web

- 浏览器默认字号可能是用户自定义的，不要假设 16px
- 优先用 `rem` + `em`，尊重用户字体缩放
- 表格、密集数据用 `px` 保证像素对齐

### 小程序 vs Web 的 style 覆写建议

| 项 | Web 基准 | 小程序建议 |
|---|---|---|
| 输入框高 | 40–44px | 48–52px |
| 按钮高 | 40px | 48px |
| 圆角 | 4–8px | 8–16px（小程序组件默认偏圆） |
| 正文字号 | 15–16px | 15–16px（1px ≈ 2rpx） |
| 边框 | 1px | 1px（不要用 rpx） |

## 交付前的单位自查

- [ ] 规格里每个数值都标注了单位（px / rpx / ms）
- [ ] 小程序稿的热区 ≥ 88rpx
- [ ] 边框、阴影、分隔线用 px 不用 rpx
- [ ] 字号在 iOS 上不小于 16px（或说明为何更小）
- [ ] 底部安全区已预留
- [ ] 深色模式两套数值都已换算（不是只换了一个）

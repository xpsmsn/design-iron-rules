# L0 铁律 + L1 定律

## L0 · 10 条不可协商铁律

违反任意一条，方案不得进入交付。风格偏好、审美主张、客户要求都不能豁免 L0；确有冲突时按第 4 步「压 L0」处理。

### 铁律 1 · 可读性

- 正文与背景对比度 ≥ 4.5:1；大字号（≥ 24px，或 ≥ 18.66px 且 ≥ 700 字重）≥ 3:1
- 界面组件轮廓、图标、状态指示与相邻色对比度 ≥ 3:1
- **功能性边框**（输入框、复选框边界、选中态描边）≥ 3:1——它们传达"这是可交互的"，属于组件轮廓
- **纯装饰分割线**（卡片之间的 hairline、段落分隔）豁免。`#E2E8F0` 配 `#F8FAFC` 只有 1.18:1，这是正常的，不要为了达标把分割线加深到破坏轻盈感
- 禁用态是唯一允许降到 3:1 的场景，且必须同时有非颜色线索（文案说明）
- **颜色不得作为唯一信息载体**。红/绿必须配图标或文字；选中态必须配形状或字重变化；图表必须配直接标注或数据标签

> 高频翻车：占位符文字、次要说明文字、图表网格线、禁用按钮、图标色。这五处是最常见的对比度不足来源。

### 铁律 2 · 可达性

热区按平台分档，**不要用一个数值当普适标准**：

| 平台 | 最小热区 | 依据 |
|---|---|---|
| Web / H5 | 44 × 44 CSS px | 通用默认值，鼠标与触屏通吃 |
| Web 高密度 | 24 × 24 CSS px（WCAG 2.5.8 最低线）+ 相邻间距 ≥ 8px | 仅族 1.4，且必须提供非鼠标操作路径 |
| iOS | 44 × 44 pt | Apple HIG |
| Android | 48 × 48 dp | Material |
| 小程序 | 88 rpx（@375 宽 ≈ 44px） | 换算见 `units-and-platforms.md` |

其他硬性要求：

- 相邻热区间距 ≥ 8px，不得重叠或紧贴
- 键盘可达：所有可交互元素有可见焦点态，Tab 顺序与视觉顺序一致，焦点不可被遮挡
- 热区尺寸可以大于视觉尺寸（用 padding 扩展），反过来不行——看着能点但点不到是铁律违反
- 手势必须有等效的点击路径

### 铁律 3 · 主动作可辨

- 视图内必须有明确的主动作，且用户能在 1 秒内认出是哪一个
- 主动作文案必须是动词短语（「提交申请」），不是名词或状态描述（不要写「申请提交」「已提交」）
- 破坏性操作绝不能与主动作争抢视觉权重

> 「每屏只有一个主操作」是 **L1 定律的默认做法，不是 L0**（见下方「层级与主动作」）。确有并列主动作的场景——命令面板、多入口落地页、分步流程的并列分支、对比型 CTA 组——只要每个动作权重可辨、文案是动词短语，就不算违反，此时在规格里写明"为何并列"即可。不要为了凑铁律把真实入口硬砍掉一个。

> 反面：三个同样式按钮并排且都像主动作、把危险操作做成主按钮、主按钮写「提交」。

### 铁律 4 · 状态完备

每个依赖数据或异步过程的组件，必须定义且实现以下 5 态：

| 状态 | 要求 |
|---|---|
| 加载中 | 有骨架屏或进度指示；> 400ms 无响应必须提供进度或可离开 |
| 空 | 说明「为什么空」+ 下一步动作；区分首次为空 与 筛选后为空 |
| 错误 | 说明发生了什么 + 是否可重试 + 重试按钮；不显示技术堆栈或错误码给普通用户 |
| 成功 | 数据本身即状态；必要时加确认反馈 |
| 无权限/受限 | 明确告知缺少什么权限、如何申请 |

缺任一态视为未完成。空态是最常被跳过的一态，也是最影响新用户体验的一态。

### 铁律 5 · 不丢数据

- 破坏性操作（删除、批量清除、不可撤销的提交）必须二次确认，确认文案写明**具体后果与影响范围**（「将永久删除 12 条记录，不可恢复」而非「确定删除吗？」）
- 默认给可撤销路径：Toast 内 5–10 秒撤销按钮优先于确认弹窗
- 表单提交失败时保留所有已填内容
- 不可逆操作不得与普通操作使用同样的视觉权重

### 铁律 6 · 一致性

- 同一语义全局只有一种视觉表达。相同含义的颜色/图标/文案不得在不同页面出现分歧
- 所有间距、字号、圆角、阴影、动效时长必须来自同一套 token，**规格里不允许出现 token 表之外的数值**
- 同一类组件在不同页面行为一致（点开方式、关闭方式、选中表现）
- 术语统一：同一个对象在所有文案中用同一个词，不要混用「删除 / 移除 / 清除」

> 本条只约束**规格中数值的来源一致性**。代码层面的硬编码魔数、组件库 API、CSS 写法与构建配置属于代码实现，不在本 skill 范围内，也不计入评分。

### 铁律 7 · 动效不阻路

- 动效服务于理解（说明空间关系、来源去向、状态变化），不服务于炫耀
- 时长：微交互 100–200ms，元素进出 200–300ms，页面转场 ≤ 400ms。超过 400ms 用户会感到卡
- 动效不得延迟用户下一步操作（禁止「动画播完才响应点击」）
- 必须响应 `prefers-reduced-motion`：降级为透明度/瞬时切换，取消位移、缩放、视差
- 循环动效（呼吸、飘浮）必须有停止条件，不得持续占用注意力

### 铁律 8 · 反馈即时

- 任何用户动作在 100ms 内产生可见反馈（hover / press / active 三态齐全）
- 反馈延迟 > 1s 的操作必须异步化并展示进度
- 提交类操作必须防重复点击（按钮进入 loading 且禁用），直到返回明确结果
- 乐观更新仅用于可逆操作；不可逆操作必须等服务端确认

### 铁律 9 · 输入可恢复

- 校验失败不清空用户已填内容，不重置光标位置
- 错误提示指向**具体字段**并说明**如何修复**（「邮箱格式应为 xxx@xxx.com」而非「格式错误」）
- 校验时机：失焦时校验格式，提交时校验全部，实时校验仅用于非阻塞提示
- 支持粘贴、自动填充、输入法中（composition）状态，不打断中文输入
- 提供撤销路径；密码类字段明确标注是否可复制

### 铁律 10 · 密度自适应

- 布局在 360px / 768px / 1280px / 1920px 四档下均成立
- 不靠固定像素宽度硬撑，不出现横向滚动条（数据表格除外，且表格需提供冻结列或横向滚动提示）
- 内容用 `min / max / flex / grid` 约束，不用 `width: 500px` 这类死值
- 超长文本、超大数值、混排文案不破版（见 `references/states-feedback.md` 边界清单）

## L1 · 定律（可调整，但须书面说明）

风格宪法可以覆写这些值，但覆写必须记录在规格的 token 表里并标注来源。

### 间距（4px 基线）

`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96`

规则：
- 组件内边距与组件间距取同一套值，不用「内 12 外 16」这种随手搭配
- 相关元素间距 < 同组元素间距（亲密性原则）
- 段落之间用空行或容器分隔，不用连续空行堆叠

### 字号

`12 · 13 · 14 · 16 · 18 · 20 · 24 · 30 · 36 · 48 · 64 · 96`

- 正文 ≥ 15px，长文阅读场景 ≥ 17px
- 相邻两级标题字号比 ≥ 1.2，否则层级不成立
- 一个视图内字号档位 ≤ 6 档

### 行高

- 正文 1.5–1.7（中文建议 1.6–1.8，中文方块字需要更大行距）
- 标题 1.1–1.3
- 表格、多行文本框 1.4–1.5

### 字重与字距

- 字重 ≤ 3 档：`400 / 500 / 700`。层级靠字号 + 颜色差拉开，不靠无限加粗
- 中文大标题字距 `-0.02em`，超大字号 `-0.03em`；小字号正文不加负字距

### 层级与主动作

- **默认**：每视图 1 个主 CTA（主色实心按钮），次级动作用次级 / 幽灵 / 文字按钮或菜单承载，按视觉权重降序排列
- **允许并列主动作**，满足以下三条即可：① 每个动作视觉权重可辨（填充 / 色相 / 尺寸至少一项有区分）；② 每个动作文案是动词短语；③ 规格中写明为何并列
- 合法并列场景：命令面板、多入口落地页、分步流程的并列分支、对比型 CTA 组
- 破坏性操作不参与并列，一律降到次级样式或危险色

### 圆角

`0 · 4 · 8 · 12 · 16 · 24 · full`

- 同一层级的组件圆角必须一致；嵌套时内层圆角 = 外层圆角 − 内边距
- 输入框/按钮 6–8px；卡片 12–16px；标签/徽标 full
- 同一视图内圆角档位 ≤ 3

### 阴影（语义 = 离表面的距离）

| 级 | 用途 | 建议值 |
|---|---|---|
| 0 | 平面元素 | 无阴影，用边框或底色区分 |
| 1 | 悬停 | `0 1px 2px rgba(0,0,0,.06), 0 1px 3px rgba(0,0,0,.1)` |
| 2 | 卡片/浮起 | `0 4px 12px rgba(0,0,0,.08)` |
| 3 | 弹层 | `0 12px 32px rgba(0,0,0,.12)` |

阴影色统一带品牌色相偏移（不是纯黑），避免脏灰感。

### 栅格

- 12 列，gutter 16–24px，页边距 16（移动）/ 24（平板）/ 32（桌面）
- 内容最大宽 1200–1440px；**阅读类内容限宽 680–760px**，超宽行会毁掉可读性
- 响应式断点：360 / 768 / 1024 / 1440

### 色彩

- 1 主色 + 1 强调色 + 1 中性色阶（8–12 档）+ 4 语义色（成功/警告/危险/信息）
- 主色按钮、强调色用于链接与高亮、语义色只表达语义（不要用绿色做品牌色，避免与成功状态混淆）
- 中性色阶必须覆盖：页面底色、卡片底色、分割线、三级文字、边框
- 暗色模式不是把颜色反相：中性色阶需重新标定，正文纯白会眩光，建议 #E6E6E6 左右

### Z 轴层级（6 级）

`背景 0 · 内容 10 · 悬浮 300 · 吸顶 400 · 弹层 1000 · 全局提示 2000`

吸顶元素（顶栏、底栏）必须考虑内容滚到下方时的可读性：要么加毛玻璃 + 边框，要么加渐变遮罩。

### 图标

- 同一层级只用一套图标库，全局线宽统一（1.5px 或 2px，选定后不再混用）
- 图标尺寸随字号：12 / 16 / 20 / 24 / 32
- 图标不单独承载语义，必须配文字或 `aria-label`

## L0 自检清单

出稿前逐条打勾：

- [ ] 正文、次要文字、占位符、图标、禁用态全部达标对比度
- [ ] 所有可交互目标 ≥ 44×44（或族 1.4 的 24×24 + 8px 间距豁免）
- [ ] 主动作可辨，且为动词短语（并列主动作需已说明理由）
- [ ] 每个数据组件有 5 态
- [ ] 破坏性操作二次确认 + 可撤销
- [ ] 规格内无表外数值，全部来自 token
- [ ] `prefers-reduced-motion` 已处理，动效无 > 400ms 阻塞
- [ ] 按下/提交类操作有即时反馈与防重复提交
- [ ] 表单失败保留已填内容，错误定位到字段
- [ ] 360 / 768 / 1280 / 1920 四档均成立

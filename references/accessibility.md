# 无障碍铁律

L0 铁律的展开。面向中国大陆高校学生场景时，额外注意中文排版与国内浏览器/系统差异。

## 对比度

| 内容 | 要求 | 依据 |
|---|---|---|
| 正文文字 | ≥ 4.5:1 | WCAG 2.1 AA |
| 大字号（≥ 24px，或 ≥ 18.66px + 700） | ≥ 3:1 | WCAG 2.1 AA |
| 图标、图形、边框 | ≥ 3:1 | WCAG 1.4.11 |
| 焦点指示 | ≥ 3:1 | WCAG 2.4.11 |
| 禁用态 | 豁免 | 但必须有非颜色线索 |

**颜色不是唯一信息载体**（WCAG 1.4.1）。红/绿必须配图标或文字；图表必须配直接标注、纹理或数据标签。

### 高频不达标位置

占位符文字 · 次要说明 · 图表网格线 · 禁用按钮 · 图标 · 边框 · 玻璃拟态上的文字 · 浅色提示语（"点击这里"灰字）· 表单错误提示在浅底上

### 中文特有的坑

- 灰色文字在低亮度屏幕上对比度下降约 15%，按 4.8:1 校核更稳
- 细字重（300 以下）中文字形笔画在屏幕上会消失，正文不低于 400
- 抗锯齿的中文字形笔画间隙小，浅色底 + 深色字的对比度要求比西文高
- 雅黑 / 苹方在部分设备上小字号渲染偏细，可考虑思源黑体或适当加重字重

## 键盘可达

- 所有交互元素可用键盘到达
- Tab 顺序 = 视觉顺序（从上到下、从左到右），不靠 `tabindex` 手动打乱
- 焦点态**必须可见**：2px 实心描边 + 2px 偏移，焦点环与相邻色对比 ≥ 3:1
- 焦点不可被吸顶元素遮挡（`position: sticky` + `z-index` 的常见问题）
- 焦点环不能用 `outline: none` 移除而不替代
- 打开弹层时焦点移入弹层，关闭时焦点返回触发元素
- Esc 关闭弹层（模态弹层必须）
- 焦点陷阱：模态弹层内 Tab 不应跳到背景内容

## 语义结构

```html
<header> <nav> <main> <aside> <footer>
<h1>—<h6> 层级连续不跳级
<button>  可点击元素不用 <div onclick>
<a href>  跳转不用 <div onclick>
<label for>  表单标签与控件关联
<main>     每页有且仅有一个
```

- 页面标题唯一；`<h1>` 每页一个
- 列表用 `<ul>/<ol>`，表格数据用 `<table>` 与 `<th scope>`
- 图标按钮必须有 `aria-label`
- 状态变化用 `aria-live="polite"` 播报（如「已添加 3 项」）

## 图像与图标

- 有信息含义的图有 `alt`
- 装饰性图 `alt=""`
- 图标不单独承载语义（配合文字或 `aria-label`）
- 复杂图表给数据摘要，不能只给图片

## 表单

- 每个字段有可见 `<label>`，不只靠 placeholder
- 错误信息：`aria-describedby` 关联到字段，`aria-invalid="true"` 标记
- 错误提示说明**怎么改**，不只是指出错了
- 必填标记用文字「*」+ `required`，不只靠颜色
- 分组用 `<fieldset>` + `<legend>`
- 避免 placeholder 充当标签（标签消失后用户失去上下文）

## 动效与前庭障碍

- 必须响应 `prefers-reduced-motion`（见 `motion.md`）
- 自动播放的动画/轮播必须有暂停控制
- 视差、旋转、大幅位移动效必须可关闭
- 闪烁不得超过每秒 3 次（WCAG 2.3.1，光敏性癫痫风险）

## 触摸与移动端

- 热区 ≥ 44×44 CSS px
- 相邻热区间距 ≥ 8px
- 不用 hover 作为唯一的信息获取方式（触屏没有 hover）
- 拇指可达区：主要操作放在屏幕下半部
- 手势有可见替代（手势操作必须有点击等效路径）

## 中文排版无障碍

- 字号 ≥ 15px（正文）
- 行高 1.6–1.8
- 行长 20–40 个汉字（680–760px）
- 段落之间有明确间隔，不靠连续空行
- 中文标点不出现行首（`text-spacing-trim` 或手动处理）
- 中英文之间加空格或自动间隙，提升可读性
- 不用手写体、极细字重、纯装饰性字体承载正文

## 检验流程

### 0. 先跑脚本

对比度是唯一**不该靠手算或肉眼**的检查项。WCAG 相对亮度公式在逐项检查十余组配色时极易出错，且肉眼判断对比度本身不可靠。

```bash
node scripts/contrast.js "#111827" "#F7F8FA" 15 400   # 前景 背景 字号 字重
node scripts/contrast.js --batch pairs.txt              # 批量，每行 前景,背景,标签
```

`pairs.txt` 示例：

```
#111827,#F7F8FA,列表页正文
#6B7280,#F7F8FA,次要文字
#FFFFFF,#3B82F6,主按钮文案
#3B82F6,#FFFFFF,链接与图标
```

批量模式在存在未达标项时返回退出码 1，可直接接进 CI。

余下步骤靠人工：

1. **对比度**：脚本跑完，剩余例外情况（渐变上的文字、玻璃拟态的合成底色）仍需真机取色器复核
2. **键盘走查**：拔掉鼠标，只用 Tab / Enter / Space / Esc / 方向键完成主流程
3. **缩放**：浏览器放大 200% 不出现横向滚动与内容截断
4. **暗色模式**：单独跑一遍脚本（暗色最易不达标）
5. **色觉模拟**：用色觉模拟工具检查红/绿区分（红绿色盲约 8% 男性人口）
6. **屏幕阅读器**：至少走一遍主流程（VoiceOver / NVDA）
7. **打印**：如果支持打印，检查深色背景块的处理
8. **单位**：按 `units-and-platforms.md` 核对小程序 rpx / iOS pt 换算

## 高校场景特别注意

- 老旧笔记本屏幕亮度低、对比度差 → 提高基础对比度余量
- 投影仪（阶梯教室、多媒体教室）会严重失真 → 提供高对比模式，避免关键信息依赖细线
- 部分学生使用系统级高对比度模式 → 不要用 `!important` 覆盖系统色彩
- 移动端碎片化阅读 → 单手可达、字号不小于 15px
- 中文输入法组合态（拼音候选框弹出时）不能触发校验报错

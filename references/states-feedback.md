# 状态与反馈

铁律 4 的展开：每个组件必须实现的 5 态，以及边界情况清单。

## 五态

### 1. 加载中

- 结构已知 → 骨架屏（形状与真实内容一致）
- 结构未知 → 进度指示 + 区域占位（保持布局不跳动）
- 局部加载 → 局部骨架，不整页遮挡
- > 3s → 加进度条 + 文案说明 + 取消入口
- 不要用整屏遮罩 + 旋转图标遮住已经加载好的内容

### 2. 空

空态分四种，文案和动作都不同。**只用一种通用空态是最常见的体验缺陷。**

| 类型 | 场景 | 文案要点 | 动作 |
|---|---|---|---|
| 首次为空 | 用户还没创建过 | 说明这个功能能带来什么价值 | 创建按钮（主操作） |
| 筛选为空 | 有数据但筛选后没有 | 明确是筛选条件导致 | 清空筛选条件 |
| 搜索为空 | 搜索无结果 | 建议换关键词、放宽条件 | 推荐内容 / 清空搜索 |
| 权限为空 | 用户无权访问 | 缺什么权限、找谁申请 | 申请权限入口 |

规则：
- 空态必须有「为什么空」+「下一步做什么」，不能只有一个插画
- 空态里的按钮是页面的主动作（此时铁律 3 的主动作落在空态上，文案仍须是动词短语）
- 首次为空是最有价值的空态——它是新用户教育机会，不要浪费成一张灰色图

### 3. 错误

分层给信息，不同错误给不同处理：

| 错误 | 文案 | 动作 |
|---|---|---|
| 网络错误 | 「网络连接失败」+ 原因 | 重试 |
| 权限不足 | 「你没有访问权限」+ 如何申请 | 申请 / 返回 |
| 输入非法 | 定位到字段，说明怎么改 | 就地修正 |
| 系统故障 | 「服务暂时不可用」+ 不要暴露错误码 | 重试 + 稍后再试 |
| 未找到 | 「内容不存在或已删除」 | 返回 / 回到列表 |

规则：
- 不给普通用户看技术错误码、堆栈、接口名
- 错误位置贴近出错的元素，不全部堆在页面顶部
- 可重试的错误必须给重试按钮
- 局部错误不整页报错

### 4. 成功

- 成功本身是状态（数据出现即成功）
- 需要确认的操作给短暂反馈：Toast（4s 自动关闭）+ 撤销入口，或内联变化
- 提交成功给出明确的下一步（「已提交，审核约需 2 个工作日」），不是只说「操作成功」

### 5. 无权限 / 受限

- 明确告知缺少什么权限、如何申请
- 部分受限时展示可访问的部分 + 明确标记受限部分，不要整体模糊
- 不用「暂无权限」四个字打发——用户不知道该找谁

## 边界情况清单

每个组件按这份清单自查：

### 文本
- [ ] 超长文本：标题截断方式（省略号 / 换行 / 两侧渐隐）
- [ ] 中英文混排
- [ ] emoji 与特殊符号
- [ ] 含用户输入的文本不可 HTML 注入
- [ ] 空字符串与纯空格区别处理

### 数值
- [ ] 0 值（不是空态，是有效的 0，要显示）
- [ ] 极大值（`999,999,999+` 不撑破布局）
- [ ] 负数
- [ ] 百分比与小数精度一致
- [ ] 数字右对齐 + `tabular-nums`
- [ ] 单位不可省略（0.0 kg 与 0 有意义区别）

### 集合
- [ ] 1 项 / 2 项 / 大量（1 项时布局不塌，多时正常滚动）
- [ ] 空数组 / null / undefined 三态处理一致

### 视口
- [ ] 360px 窄屏
- [ ] 1920px 宽屏不出现大片空白与错位
- [ ] 横屏 / 竖屏切换
- [ ] 安全区（刘海屏底部）
- [ ] 软键盘弹出时表单不被遮挡

### 环境
- [ ] 弱网 / 超时
- [ ] 重复提交（按钮禁用 + 请求去重）
- [ ] 断网时的操作提示
- [ ] 服务端返回异常结构（不能因数据形状变化而白屏）

### 国际化
- [ ] 文本长度膨胀 30% 仍不破版（德语通常比中文长 2–3 倍）
- [ ] 日期格式 / 时区
- [ ] RTL 布局（如需要）

## 反馈模式表

| 场景 | 模式 | 时长 |
|---|---|---|
| 悬停 | 视觉态变化 | 即时 |
| 按下 | 缩放 0.97 或位移 1px | 80ms |
| 已提交（进行中） | 按钮 loading + 禁用 | 至返回 |
| 成功（可撤销） | Toast + 撤销按钮 | 5–10s |
| 成功（不可撤销） | Toast | 4s |
| 错误（可重试） | 内联错误 + 重试按钮 | 常驻 |
| 错误（全局） | 顶部/底部条 | 6s |
| 信息提示 | Tooltip / Popover | 用户控制 |

规则：
- 破坏性操作优先用「立即执行 + 可撤销」（Toast 撤销）而非「确认弹窗 + 执行」。前者打扰更少、可逆性更强
- 不能撤销的操作才用确认弹窗
- 提交反馈不能只用颜色变化，必须有可感知的形式变化（图标、文字、位置）

## 加载与布局稳定性

- 所有异步内容预留空间，避免加载后布局跳动（CLS）
- 骨架屏尺寸 = 真实内容尺寸
- 图片未加载时保留宽高比容器
- 字体加载使用 `font-display: swap` + 调整回退字体度量
